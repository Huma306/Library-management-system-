Advanced Task Specification

Issuing a Book as an ACID Transaction

Project 1 Requirements

SQL Transactional Procedure: 

START TRANSACTION;

-- Step 1: Check available copies with row lock
SELECT available_copies 
FROM Books 
WHERE book_id = :book_id FOR UPDATE;

-- Step 2: Rollback if copies are 0
IF available_copies <= 0 THEN
    ROLLBACK;
    SIGNAL SQLSTATE '45000' 
    SET MESSAGE_TEXT = 'Rollback: Zero available copies!';
END IF;

-- Step 3: Insert into Loans & Decrement available_copies together
INSERT INTO Loans (book_id, member_id, issue_date, due_date)
VALUES (:book_id, :member_id, :issue_date, :due_date);

UPDATE Books 
SET available_copies = available_copies - 1
WHERE book_id = :book_id;

COMMIT;

Why is Transaction Atomicity Vital?

If the system simply executed an INSERT without decrementing available_copies inside the same atomic unit of work, a server crash or database network partition would result in book inventory drift.

In our frontend engine ([`js/db.js`](file:///c:/Users/zulqa/OneDrive/Desktop/New%20folder/js/db.js)), issueBookTransaction() encapsulates both state modifications in a single atomic commit, rolling back immediately if available_copies ≤ 0 or if the member holds 3 active books.
